# Collector 测试治理

## 文档定位

本文是 RebootSnap collector 实现必须遵守的测试治理规范。本文在 ADR 0002（`docs/decisions/0002-human-ai-governance.md`）要求的采集测试治理门槛上展开，是 collector 测试的单一权威来源。

本文覆盖发行版兼容范围定义、能力探测策略、可复现测试样本规范和最小测试覆盖要求。具体测试框架选型、测试命令和 CI 配置在 collector 实现阶段定义，但必须遵守本文的覆盖要求和样本格式约束。

## 发行版兼容范围

### 首轮目标

| 维度 | 目标 |
| --- | --- |
| 发行版 | Rocky Linux 8.x |
| 初始化系统 | systemd >= 239 |
| 内核版本 | 4.18.x（对应 Rocky Linux 8 的稳定内核基线） |
| 架构 | x86_64 |

首轮开发和测试只在此目标上验证正确性。在其他发行版、内核版本或架构上运行不拒绝，但不承诺行为一致，必须在输出中明确标注 `unsupported platform`。

### 升级路径

后续版本扩大兼容范围前，必须先更新本文并补充对应测试样本。发行版兼容范围是稳定设计约束，不能只在实现中隐式扩大而不在本文声明。

### 非目标系统行为

在非目标系统上，collector：

- 允许运行，但每个采集接口都必须做能力探测（见下节），不可用时记录 `unavailable` 而非崩溃。
- 必须在输出头部记录检测到的发行版、内核版本和 systemd 版本，供报告层和排障人员判断数据可信度。
- 不应因 systemd 不可用就整体退出；应降级到 procfs/sysfs 直接读取，并标注降级范围。

## 能力探测策略

### 接口可用性探测

每个采集逻辑单元在执行业务采集前，必须先探测目标接口或依赖是否存在。探测必须：

- 使用开销最低的检查方式（如 `stat()`、`access()`、连接后立刻断开），不在探测阶段执行实际数据读取。
- 在采集结果中显式记录探测结论。对每个目标接口或依赖，输出必须至少区分以下三种状态：

| 状态 | 含义 | 示例 |
| --- | --- | --- |
| `available` | 接口存在且可访问 | dmesg ring buffer 可读 |
| `unavailable` | 接口不存在或不适用 | `/sys/kernel/debug/tracing/` 未挂载 |
| `denied` | 接口存在但权限不足 | nftables 规则集需要 `CAP_NET_ADMIN` |

- 不允许将状态静默模糊为「接口可用但返回空结果」和「接口不可用」两种情况。如果接口存在、可访问且查询返回空结果，应记录为 `available` + 空结果，而不是 `unavailable`。

### 内核特性检测

依赖内核编译选项或版本特性的采集接口，必须在探测阶段检测对应特性是否存在：

- 优先通过 sysfs/procfs 节点存在性检测（如 `/proc/pressure/` 检测 PSI 支持）。
- 其次通过内核版本判断（如 `requires kernel >= 5.x`）。
- 再次通过实际读取尝试。
- 不依赖 `/boot/config-*` 检查内核编译选项，因为该文件可能不存在或不反映当前运行内核。

### 权限降级探测

每次运行时，collector 应在启动阶段检查有效权限并缓存探测结果：

- 确认 root 或特定 capability 是否存在。
- 每个采集逻辑单元在执行业务采集前，用缓存的权限探测结果判断是否可以执行。
- 因权限不足降级时，记录 `denied` 状态和缺少的具体权限。

### 降级与失败区分

| 路径 | 定义 | 测试要求 |
| --- | --- | --- |
| 预期降级 | 接口不可用、权限不足、发行版不匹配——collector 正确记录原因并继续 | 必须测试 |
| 非预期失败 | 接口存在且可用但采集逻辑 bug 导致 crash、hang、panic、错误输出 | 必须测试 |
| 预期截断 | 输出达到大小上限或条目数上限——collector 正确标记截断并继续 | 必须测试 |

## 可复现测试样本

### 样本形式

测试样本采用 mock 文件系统树的方式：

- 在测试目录中构建精简的 procfs 和 sysfs 目录结构。
- 每个 mock 节点只包含对应合法字段的最小有效内容。
- 不需要完整的 Linux 环境；测试运行时不依赖 `/proc` 和 `/sys` 的宿主机挂载。

### 最小测试场景

至少覆盖以下五种场景的快照：

| 场景 | 特征 | 用途 |
| --- | --- | --- |
| 正常系统 | 全部 `必采` 接口可用，mock 数据合法 | 验证正常采集链 |
| 资源紧张 | 部分 mock 节点不存在（如 PSI 未编译），pid 数接近截断上限 | 验证降级 + 截断 |
| 部分接口缺失 | 模拟无 systemd、无 conntrack、无 BPF 的环境 | 验证能力探测和 `unavailable` 记录 |
| 权限不足 | 模拟 hidepid=1、CAP_NET_ADMIN 缺失、tracefs 不可读 | 验证 `denied` 记录和降级继续 |
| 异常数据 | mock 节点返回超预期的值（负值、超长行、二进制内容） | 验证 collector 不解析失败、不 crash |

### Fixture 维护规则

- 每个 mock 节点文件必须注释其模仿的合法 procfs/sysfs 路径和预期字段名。
- 每次新增 `必采` 采集项时，必须同步更新对应场景的 fixture。
- 每次 `选采` 变为 `必采` 时，必须从 `选采` 专用 fixture 迁移到正常系统场景。
- fixture 不包含敏感信息、机密材料或真实主机数据。

## 测试覆盖要求

### 必采项测试

每个进入默认 collector 范围的采集项必须通过以下测试：

| 测试类型 | 覆盖要求 | 失败判定 |
| --- | --- | --- |
| 正常路径 | 在正常系统场景下，采集项输出合法且完整的结构化数据 | 无输出 / 输出格式错误 |
| 降级路径 | 在对应接口不可用或被拒绝时，记录 `unavailable` 或 `denied` 并继续 | 崩溃 / hang / 未记录原因 |
| 超时行为 | 在注入的慢 mock 上验证超时触发和部分输出 | 超时后未继续 / 无超时日志 |
| 截断行为 | 输入条目数或输出大小超过上限时正确截断并标记 | 无截断标记 / 崩溃 |
| 权限不足路径 | 对需要特权的接口，在无特权条件下验证降级 | 尝试提权 / 崩溃 |

### 降级路径测试

- 每个有 `必采` 决策的采集项，至少有一个测试验证其核心依赖不可用时的行为。
- 降级不应导致整体 collector 退出或死循环。
- 降级标记（`unavailable`、`denied`、`timed out`、`truncated`）在输出中必须具备可解析的结构。
- 降级时不能输出空数据却声称采集成功。

### 全局超时测试

- 注入至少一个模拟卡死 350 秒的采集项，验证全局 300 秒超时优雅退出。
- 超时后的输出必须包含已完成采集项的数据和未完成采集项的状态。

### 回归测试

- 每次修改采集逻辑或新增采集项后，必须在正常系统场景下运行全量测试。
- 每次修改截断/超时逻辑后，必须在资源紧张和异常数据场景下运行对应测试。
- CI 中对正常系统场景和部分接口缺失场景的测试为 push 阻塞项；资源紧张和异常数据场景可设为 non-blocking 但必须运行。

## 测试失败处理

### 失败分类

| 类别 | 定义 | 处理方式 |
| --- | --- | --- |
| 预期降级 | 接口不可用、权限不足——collector 正确记录并继续 | 不计入失败 |
| 非预期崩溃 | SIGSEGV、SIGABRT、panic、unhandled exception | 阻塞合入 |
| 非预期挂起 | 超时未返回、死循环 | 阻塞合入 |
| 输出格式错误 | 缺少必要字段、无法解析、错误数据 | 阻塞合入 |
| 截断逻辑错误 | 未标记截断、截断但丢失已采集数据 | 阻塞合入 |
| 安全违规 | 输出中包含禁止采集的内容（见 `docs/collector-security-governance.md`） | 阻塞合入 |

### 测试环境约束

- 测试不得依赖宿主机真实硬件状态、网络连接或外部服务。
- 测试不得修改宿主机内核参数、挂载点或服务状态。
- 测试必须是幂等的——多次运行结果一致。
- CI 中的测试必须在不依赖 `/proc` 宿主机挂载的条件下运行（通过 mount namespace 隔离或 mock 文件系统）。
