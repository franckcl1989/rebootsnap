# 术语表

## 文档定位

本文定义 RebootSnap 文档、工具和变更记录中应稳定使用的术语。

新增稳定术语时，必须说明含义、边界和首选写法。术语表不收录临时任务名、一次性分支名或只在单个段落中使用的普通词。

## 稳定术语

### RebootSnap

用于在 Linux 服务器重启前采集操作系统运行时现场，并为重启后排障和根因分析保留系统证据的项目。

### Linux OS 运行时信息

在一次 Linux 启动实例中，由内核、初始化系统、系统守护进程和 OS 子系统维护的当前状态、临时对象、运行时关系、易失缓冲、缓存、计数器或实际生效状态。

详细边界以 `docs/linux-runtime-info-categories.md` 为准。

### 重启失真

运行时信息在系统重启后消失、重置、重新生成，或失去对原现场证明意义的现象。

### 运行时现场

重启前某一时刻 Linux OS 层面的实际状态集合。它强调当前 boot 中的对象身份、状态值、时间关系和引用关系。

### 系统证据

能够支持重启后排障、事实复原或根因分析的 OS 层信息。系统证据可以来自运行时现场、持久化日志或配置，但 RebootSnap 的核心对象是重启前运行时现场。

### 稳定入口

人类和 AI 都应优先读取和引用的权威文件或命令，例如 `AGENTS.md`、`docs/index.md`、`docs/project-map.yml` 和 `scripts/verify.sh`。

### 设计约束

后续文档、实现或工具必须遵守的决策性规则。设计约束必须能被引用、审查和追溯。

### 采集项

未来实现中对某一类运行时信息的具体采集对象、接口、字段或命令。本文档阶段只定义概念，不固定采集实现。

### 二级分类

在 `RT-01` 到 `RT-21` 大类之下继续拆分的稳定信息类别。二级分类用于承接后续采集项、数据模型和报告视图，但本身不等同于采集命令、字段或文件路径。

### 三级分类

在 `RT-xx-yy` 二级分类之下继续拆分的候选采集项组，使用 `RT-xx-yy-zz` ID。三级分类用于后续最终采集决策筛选，不直接固定采集命令、字段结构或权限策略。

### 变更管理

对提交信息、变更记录、验证说明和强制校验的统一管理。权威规范是 `docs/change-management.md`。

### 有界执行

collector 每个采集项必须设定超时、输出大小上限和条目数上限，超过限制时截断、降级并继续，不因单项失败中断整个采集过程。权威约束见 `docs/collector-security-governance.md`。

### 降级

接口不可用、权限不足或超时时，collector 记录不可用原因并继续后续采集项，不崩溃、不挂起、不尝试提权。降级是预期行为而非失败。

### 能力探测

在执行业务采集前，先以最低开销方式检查目标接口是否存在、是否可访问、是否有权限，并在输出中显式记录 `available`、`unavailable` 或 `denied` 状态。权威约束见 `docs/collector-testing-governance.md`。

### 脱敏

对采集结果中的敏感字段（主机名、IP 地址、端口、用户标识、文件路径等）做掩码、哈希或省略处理。collector 默认记录原始值，不在采集阶段脱敏；脱敏由报告层或独立后处理工具执行。权威约束见 `docs/collector-security-governance.md`。

### 人与 AI 共治

人类维护者负责目标、边界和最终判断，AI 代理负责按固定入口执行可验证的分析、修改和一致性维护。共治要求规则既能被人理解，也能被工具检查。
