# 人与 AI 共治规则

## 文档定位

本文定义 RebootSnap 中人类维护者和 AI 代理共同工作的职责、边界和质量门槛。

本文不替代具体设计文档。具体设计以对应领域文档为准；当多个文档冲突时，按本文的“事实来源优先级”处理。

## 共治目标

RebootSnap 的治理目标是让人类和 AI 都能稳定理解项目：

- 人类可以快速判断项目当前状态、设计意图、变更影响和验证结果。
- AI 可以通过固定入口、稳定术语、机器可读地图和校验脚本执行一致的工作流。
- 重要规则不只写在自然语言中，还应尽量由脚本、hook 或 CI 检查。

## 事实来源优先级

出现冲突时，按以下顺序判断：

1. 当前用户明确指令。
2. 仓库内更具体的规范文档。
3. `docs/project-map.yml` 中声明的机器可读入口。
4. `docs/index.md` 中的文档索引。
5. `README.md` 中的概览说明。
6. 历史 `CHANGELOG.md` 条目。

如果冲突涉及项目目标、核心边界或不可逆修改，必须先由人类确认。

## 人类职责

- 决定项目目标、产品边界、核心术语和不可逆设计取舍。
- 审核 AI 提出的新增规范、核心分类和安全边界变化。
- 在远端仓库启用分支保护、必需 CI 和发布权限控制。
- 对 AI 无法验证的业务事实和外部约束给出最终判断。

## AI 职责

- 按 `AGENTS.md` 的必读顺序加载上下文。
- 在现有文档结构内补齐缺口，避免建立重复入口。
- 主动维护 `CHANGELOG.md`、`docs/index.md`、`docs/project-map.yml` 和相关模板的一致性。
- 对变更影响、未验证事项和需要人类确认的事项做显式说明。
- 运行 `scripts/verify.sh`，并修复能在本地合理修复的问题。

## 自主修改边界

AI 可以自主完成：

- 修复文档链接、标题结构、模板格式和索引缺失。
- 添加或改进校验脚本、hook、CI 配置和模板。
- 在不改变项目语义的前提下收敛措辞，让文档更清晰。
- 为已有设计补充例子、边界说明和验证说明。

AI 必须先确认：

- 改变 Linux OS 运行时信息的定义边界。
- 新增、删除或重编号稳定分类 ID。
- 删除历史变更记录或重写已生效的设计结论。
- 引入依赖外部服务的强制流程。
- 改变默认分支、发布策略、许可证或安全模型。

## 质量门槛

每次有意义变更必须满足：

- 变更意图可以从 commit subject 和 `CHANGELOG.md` 顶部条目读出。
- 影响范围使用稳定路径、稳定模块或稳定设计域表达。
- 设计影响写清新增、修改、保留或废弃的约束。
- 验证结果写清具体命令、检查或人工审核结论。
- `scripts/verify.sh` 通过。

## 远端治理

在文档骨架稳定后，远端默认分支应启用分支保护：

- 要求 pull request 合并。
- 要求 `Change Management` workflow 通过。
- 禁止未审查的直接推送进入默认分支。

当前如果仍处于单人本地文档落地阶段，可以先依赖本地 hook 和 CI 文件，待首次推送并确认 workflow 正常后再启用远端保护。
